# CAD2APP v2.27 변경 설명

## 왜 바꿨나

### 1) v2.26 재추출 후 원 미배정이 대량 발생
사용자 보고: **43개 결함이 원을 찾지 못함**(주황/미배정).  
원인 후보로 사용자가 지적한 대로, v2.26에 넣은 **away-leader / `minAwayGap`(40)** 조건이 너무 빡셌습니다.

이 규칙은 "원쪽 선 끝이 글자 쪽보다 확실히 더 멀어야만" 후보로 남겼습니다.  
짧거나 비스듬한 정상 지시선, 글자 박스와 원 거리가 비슷한 경우까지 한꺼번에 탈락시켜, 원을 못 붙인 채 주황 폴백으로 넘어간 것으로 보입니다.

### 2) 테두리 제외만으로도 62/71은 잡혔을 가능성
사용자 질문: 텍스트 테두리(이중변 약 0.735mm) 제외가 제대로 되면, away-leader 없이도 62/71 류 오배정이 고쳐지지 않느냐?

**답: 예, 그럴 가능성이 높습니다.**  
62/71 오배정의 핵심은 글자 박스의 짧은 테두리 변이 "가장 가까운 지시선 끝"으로 잡히던 문제였고, v2.26의 **이중변·4~8선·박스둘레 LINE 제외**가 그 뿌리를 칩니다.  
away-leader는 그 위에 얹은 추가 하드 게이트라, 테두리가 잘 빠지면 굳이 원쪽이 더 멀다는 조건을 강제할 필요가 거의 없습니다.

그래서 v2.27은 **테두리 제외는 유지**하고, **away-leader 게이트만 제거**합니다.

## 어떻게 바꿨나

### A. 유지 (v2.26 테두리)
- 닫힌 4변 LWPOLY 거의-직사각형 제외
- LINE 4~8개 묶음(이중변 간격 ~0.735mm 포함) 제외
- 글자 바운딩박스 둘레에 양 끝이 붙는 짧은 LINE 제외
- 객체 삭제/변환 없음 — 지시선 후보(`lineList`)에서만 제외

### B. 제거 (away-leader)
- `minAwayGap` 40 하드 게이트 완전 제거
- 원쪽 끝이 글자에서 더 멀지 않아도, 반대쪽 끝에 같은 도면층 원이 있으면 후보로 둠

### C. 유지 (매칭 골격)
- 텍스트 실제 바운딩박스 → 남은 선 중 제일 가까운 끝 → 반대쪽 끝의 같은 도면층 CIRCLE
- v2.24식 품질점수(텍스트거리 + 원연결거리 보정) 유지. 원쪽이 더 멀면 소폭 가산점은 남기되, 탈락 조건은 아님
- v2.18식 "아무 선 최근접" 금지
- 미배정 주황 폴백은 **LEADER만**

### D. 버전 표기
- 헤더 / 명령창: `v2.27`
- JSON `version`: `2.27_keep_border_drop_away_leader`
